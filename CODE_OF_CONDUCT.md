# Code of Conduct

## The short version

Be decent. Assume the other person is acting in good faith until they give
you a reason not to. Criticise code, not people.

## What is expected

- **Technical disagreement is welcome and is the point.** Say why you think
  something is wrong, with the evidence. "This races under X" is useful;
  "this is bad" is not.
- **Be concrete.** A bug report with the command you ran and the output you
  got is worth ten describing a feeling.
- **Accept a decision once it is made.** Raise a concern with evidence; if
  the maintainer decides otherwise, that is the decision. Relitigating it in
  every thread is its own kind of harm.
- **Credit what you build on.** If you adapted something, say where from and
  check the licence.

## What is not acceptable

Harassment, personal attacks, discriminatory language, sexualised content,
deliberate intimidation, publishing someone's private information, and
sustained disruption of discussion.

This applies in issues, pull requests, commit messages and code comments —
anywhere the project's name is on it.

## Enforcement

This project currently has a single maintainer. Reports go to them, through
a private message on GitHub or by opening an issue if the matter is not
sensitive. There is no committee, no formal process and no appeals board —
saying otherwise would be inventing governance that does not exist.

What a report gets is: it will be read, and a decision will be made.
Responses range from asking someone to change their approach, through
editing or removing a comment, to blocking an account.

## Scope

This repository and its issue tracker. It is not a claim of authority over
anyone's conduct elsewhere.
